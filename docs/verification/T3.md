# T3 - Launcher wiring (what each button reads and writes)

Reasoning only (mock-based): nothing can run here (no .NET, no Revit). All four methods keep the T1 signatures `Open / Review / SolveView / Report(UIApplication)`. Every body runs inside `Guard(...)`, which catches any exception and shows it in a TaskDialog (message, details = full exception) - Revit is never crashed. Results are shown by `ShowSummary`: scalar summary lines as dialog content, the per-warning-type lines under "Show details".

Common to the three engine buttons (`RwisEngine.Run`):

- **Reads** from the model: all warnings (`Document.GetWarnings`), the failing / additional elements of each warning (category, level, bounding box, location, parameters, pin / group state), fill patterns, existing views, the active view; from the RWIS template (embedded resource) the classes, taxonomy, severity, rules and fix guide; from disk the existing report `Desktop\RWIS Reports\<model>_RWIS_Warnings_Report.xlsx` (history, manual columns, deleted-element log).
- **Plans** a fix for every warning with `preview = true` (describes only, changes nothing).
- **Writes** the Excel report (unless `SkipReport`) after the transaction is committed: `<model>_RWIS_Warnings_Report.xlsx` (sheets RWIS_Summary, All_Warnings, AICon_Change_Log, Snapshot_Log, Column_Guide and the six TBL_ tables) via a `.tmp` file and copy; if Excel has the file open, a time-stamped copy is saved and the summary says so.

## Warnings (Open)

- Reads: Revit version text only.
- Writes: nothing. Shows "Warnings window comes in the next build." (T4 replaces the body.)

## Review Warnings

Code: `RwisEngine.Run(uiapp, new RwisOptions { Action = 1 })` = v7 action 1 with all severities, no filter, no unpin, confirmations on, views on, report on.

- Reads: as above.
- Writes in the model, inside ONE transaction "RWIS Warnings - Review - 3D view per warning type (no changes)" (one Ctrl+Z): one isometric 3D view per warning type named `WRN nn - <SEVERITY> - <text>` (Description = `RWIS|<warning text>`, section box +1 m, temporary isolate, element overrides: severity colour, magenta for elements a fix would delete); existing WRN views are re-used and renamed; WRN views whose warning no longer exists are renamed `WRN -- - DONE - ...`. No element is changed, moved, joined or deleted (fixes run only as `preview`; `solveGroup` is never called in action 1).
- Writes outside the model: the Excel report. Then requests a switch to the first WRN view.
- Dialog: the v7 summary (counts, report path, health score, per-type lines with auto-fixable counts and view names).

## Solve This View

Code: first checks `RwisEngine.IsWrnView(ActiveView)` (v7's `keyOf`: Description starts with `RWIS|`). If it is not, a TaskDialog says "The active view is not a WRN review view. Run 'Review Warnings' first ..." and nothing else happens (no collection, no transaction, no report). Otherwise `RwisEngine.Run(uiapp, new RwisOptions { Action = 2 })` = v7 action 2.

- Reads: as above, plus the warning type stored in the active view's Description.
- Writes in the model, inside ONE transaction "RWIS Warnings - Solve warning type of the active WRN 3D view": the fixes of that warning type only, after v7's "Fix this warning type" confirmation (skipped for room-boundary-only fixes). Deletions of 3D elements ask first: the elements are painted magenta (kept ones green) in the active view, selected and zoomed, with Delete / Keep / Delete all (the temporary overrides are restored after the dialog). Pinned elements are not touched (message "tick 'Unpin to fix'" - there is no tick in this button, so pinned ones stay manual). The view is renamed to `WRN nn - DONE - ...` and recoloured (green = changed, via `makeView(key, true)`).
- If the type no longer exists: view renamed `WRN -- - DONE - ...`, nothing else.
- Writes outside the model: the Excel report (rows solved by the tool get status SOLVED - AICon, deleted element IDs and RED rows, plus AICon_Change_Log entries).

## Warnings Report

v7 has no report-only path (action 1 always builds or renames views inside a transaction). Implemented by reusing the collection, classification, planned-fix and report code with `RwisOptions { Action = 1, Skip3DViews = true, ReportOnly = true }`:

- `ReportOnly` (new, see T2-port.md change 7): no Transaction is created, no view is created or renamed, `solveGroup` is never called, and `preview` stays true so no fix handler touches an element. The "WRN views of vanished warnings -> DONE" renaming loop is skipped.
- Reads: as above. The planned fixes are computed in preview mode only to fill the report columns `AICon_Proposed_Fix` / `Can_AICon_Fix` (read-only API calls: `JoinGeometryUtils.AreElementsJoined`, collectors, bounding boxes, curves).
- Writes: only the Excel report (and `Desktop\RWIS Reports` if it does not exist). New warnings are added as OPEN, returning ones RE-OPENED, vanished ones SOLVED - outside AICon, a Snapshot_Log row is appended, the summary sheet and health score are recomputed. The Snapshot_Log "Action" column says "Report only - no views, no changes". The model is not modified, so no undo entry exists and the document is not marked as changed.
- Dialog: the same v7 summary (the per-type lines show status "REVIEW" and no view names).
