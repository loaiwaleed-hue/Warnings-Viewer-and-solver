`RwisGroupInfo` per group: `Key` (warning text), `Number` (nn), `Severity`, `Count`, `AutoFixable` (warnings whose plan is not MANUAL / OK), `ClassId`, `ClassName`, `Taxonomy`, `PlannedFix`, `PlanDetails`, fix guide fields, `ElementIds` (long, via `Compat.IdValue`).
- `PlannedFix` = the text of the v7 summary line ("tool: ..."): the plan of the first fixable warning (else of the first warning), up to the first `;`.
- `PlanDetails` = v7 `groupDetails` (one line per warning with its ids and plan).
- Fix guide = TBL_Fix_Guide by class ID, taxonomy-level `TAX` as fallback, risk text with the class note appended: exactly the lookup of the report columns RWIS_Recommended_Fix / Alternative / Meaning / Likely_Causes / Risk_If_Ignored.
- The scan always uses all severities and no text filter; the window filters in memory (`RwisFilter.Apply`, v7 severity order kept, stable). For Solve all the same severity set and text go to the engine (`Severities = RwisSeverity.Parse(choice)`, `Contains`), which applies the same `Matches`, so list and run agree.

Top: model + counts; Severity combo (All, CRITICAL, HIGH, MEDIUM, LOW, CRITICAL + HIGH, MEDIUM + LOW), Contains box, "Unpin to fix", "Don't ask before fixing" (same meaning as `RwisOptions.UnpinToFix` / `SkipConfirmation`), Refresh. ## What each control reads / writes

| Control | Raises | Reads | Writes |
|---|---|---|---|
| Opening the window / Refresh | `Refresh` -> `RwisEngine.Scan` | All warnings, failing / additional elements, categories, levels, bounding boxes, pin / group state, joins (planning in preview mode), the embedded template, the existing report workbook (for the class tables). | Nothing: no transaction, no view, no file, no element. The document is not marked changed. |
| Severity / Contains | none (in-memory filter of the last scan) | - | - |
| Selecting a row (400 ms after the last change) | `Open` -> `Run`, Action 1, `GroupKey`, `SkipReport` | as Refresh | One transaction "RWIS Warnings - Open 3D view of one warning type": creates / re-uses the type's WRN 3D view (isometric, section box +1 m, temporary isolate, overrides: severity colour, magenta for elements a fix would delete), renames it if the number / severity changed. No element is changed (fixes only run as preview). No Excel write. Then `RequestViewChange` to that view. Status: "Opened view: <name>". |
| Next type | the same `Open` for the next row | as above | as above. Selects the next row (no wrap; at the end: "last warning type"). It does not run the v7 action 3 dialogs (Fix / Skip / Skip all): stepping = move + open view, solving stays on "Solve this type". |
| Solve this type | `Solve` -> `Run`, Action 2, `GroupKey`, `UnpinToFix`, `SkipConfirmation` | as Refresh; the type's existing WRN view (made the active view first, outside any transaction, so the delete highlight shows there) | v7 action 2, one transaction "RWIS Warnings - Solve warning type of the active WRN 3D view" (one Ctrl+Z): the v7 "Fix this warning type" question (skipped for room-boundary-only fixes or when "Don't ask" is ticked), the fixes, magenta / green Delete / Keep / Delete all before any 3D element is deleted, pinned elements only with "Unpin to fix", the WRN view renamed `DONE` and recoloured green. The Excel report is updated as v7 does. A type with no auto-fixable warning is not run (status shows the recommended fix) - v7 would only have renamed the view DONE. |
| Solve all... | `SolveAll` -> `Run`, Action 4, filter of the list | as Refresh | After the window's Yes/No question (count of warnings and types the tool can fix, the filter, "One Ctrl+Z undoes the whole run", a warning when "Don't ask" is ticked; default button No): v7 action 4 for the filtered types in one transaction; the v7 delete confirmations still apply unless "Don't ask" is ticked; report updated. |
| After each solve | `Scan` again | | The list is rebuilt (same type stays selected, else the row at the same position); status = `RwisSummary.Condense` of the engine summary (Note, Fixed this run, Report path, Open now, Health score, Report note). |
| Open report | none (no Revit call) | checks `File.Exists` of `ReportPathFor(model)` | Starts the default application for the .xlsx. No file: status says so. |

## Threading and failure handling

- The form lives on Revit's UI thread; all Revit API calls are in `WarningsHandler.Execute` (ExternalEvent). `Finish` hands the result back; `IsDisposed` is checked on both sides.
- One request at a time (`busy`): while a request runs, Refresh / Solve / Next are disabled; a row change waits (timer retries). `Raise()` not `Accepted` -> status "Revit is busy".
- `Execute` catches everything (a failed run is rolled back by the engine's own catch) and shows `Error: ...` in the red status line. A failure of the rescan after a solve is appended to the status.
- If the active model differs from the one the list was scanned from, Open / Solve are refused with "Click Refresh first".
- The form disposes its ExternalEvent when closed; reopening creates a new pair. pyRevit reuses the loaded assembly, so the static `Instance` survives across button clicks (single instance).

## Revit API check (2022-2027)

New API use: `UIApplication.MainWindowHandle`, `ExternalEvent.Create / Raise / Dispose`, `ExternalEventRequest`, `UIDocument.ActiveView` (get / set, called outside a transaction), `FilteredElementCollector.OfClass(typeof(View3D))`, `View3D.IsTemplate`, `View.get_Parameter(VIEW_DESCRIPTION)`, `Document.Title`. All exist in every year. No `ElementId.IntegerValue` (ids via `Compat.IdValue`). BCL: no `string.Contains(char)`, ranges or index-from-end. WinForms types are always `WF.` / `SD.` qualified (Revit UI has its own `ComboBox` / `TextBox`, WPF has `Button` / `Color`).
